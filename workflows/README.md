# Conceptual workflows

`receiving.workflow.json` describes this project's receiving decisions and proposed iBlueprint orchestration role. It is review material, not a native iBlueprint file, verified API contract, or automatically executable workflow definition.

The running implementation is in `receiving/workflow.py`. Keep the conceptual description aligned with its behavior. If a vendor-native workflow is supplied later, store only material the team has the right to redistribute, identify the vendor format/version, and test it in the approved sandbox before claiming compatibility.

Donation matching is a candidate later workflow. This repository intentionally does not automate donor outreach, purchase orders, food-safety decisions, or warehouse stock changes.
